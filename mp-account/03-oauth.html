🟡 第 3 章 · 网页授权（OAuth） ​

本章信息

难度：🟡 进阶 · 预计学习 50 分钟 · 前置：第 2 章 · 自定义菜单

🎯 学习目标 ​

读完本章，你将能够：

  • 能说清 snsapi_base 与 snsapi_userinfo 两种授权范围的区别
  • 能按「授权链接 → 用户同意 → code → 换 token → 拉用户信息」讲出完整流程
  • 能正确拼接授权链接并处理回调页上的 code
  • 能定位并解决 redirect_uri 域名不一致与 code 相关的典型报错

📇 术语卡 ​

术语白话解释
OAuth一套「经用户同意后，第三方安全拿到用户信息」的标准流程
scope授权范围：base 静默只拿身份编号，userinfo 弹窗拿昵称头像
redirect_uri授权完成后微信把用户「送回」的网址，必须在后台提前登记
code授权临时凭证，5 分钟有效、只能用一次（以官方文档为准）
openid每个用户在你的公众号里的唯一身份编号，同一个用户换公众号会变
网页授权 access_token用 code 换来的票据，专门用于拉取网页授权用户信息
回调页redirect_uri 指向的那个页面，负责接住 code 并完成后续换票

⚖️ 两种 scope 的区别 ​

对比项snsapi_basesnsapi_userinfo
用户感知静默跳转，用户毫无察觉弹出「是否同意授权」页面
能拿到什么只有 openidopenid、昵称、头像、性别、地区等
适用场景只想知道「谁来了」需要「称呼用户」或展示头像

注意：权限门槛

网页授权需要认证服务号才有权限，个人订阅号没有（第 1 章讲过）。学习阶段请申请公众平台测试号：在「设置与开发」搜索「测试帐号」进入沙盒页，它的网页授权不设门槛，流程与正式号一致。

🪜 四步流程总览 ​

把 OAuth 想成一次「快递签收」：

  1. 拼授权链接：你的网页把用户带去微信的授权页（填好 redirect_uri 和 scope）
  2. 用户同意：用户点「同意」（base 范围则自动跳过）
  3. 带 code 回跳：微信把用户重定向到 redirect_uri，网址上附带一个一次性 code
  4. 换票拉信息：你的服务器用 code 换网页授权 access_token + openid，再（userinfo 时）拉用户资料

🔗 第一步：拼授权链接 ​

text
https://open.weixin.qq.com/connect/oauth2/authorize
  ?appid=APPID
  &redirect_uri=REDIRECT_URI
  &response_type=code
  &scope=SCOPE
  &state=STATE
  #wechat_redirect

四个参数（字段含义以官方文档为准）：

  • appid：你的 AppID（测试号也用它）
  • redirect_uri：授权后回跳的地址，必须先做 URL 编码（encodeURIComponent），并且域名必须与后台登记的「网页授权域名」完全一致
  • scope：snsapi_base 或 snsapi_userinfo
  • state：自定义随机串，回跳时原样带回，用于防 CSRF，如 abc123

去哪里登记域名：

  • 正式号：后台「设置与开发 → 公众号设置 → 功能设置 → 网页授权域名」（要求备案域名，以官方文档为准）
  • 测试号：沙盒页「网页服务 → 网页帐号 → 网页授权获取用户基本信息」填入你的内网穿透域名（第 0 章的隧道）

✅ 你应该看到： 域名填入并保存成功，沙盒页显示你登记的域名。

📬 第三步：回调页接住 code ​

用户同意后，微信 302 跳转到：

text
https://你的redirect_uri/?code=CODE_VALUE&state=abc123
1

回调页要做的事：从网址取出 code，立刻发给你自己的后端去换票。code 是一次性的、5 分钟内有效（以官方文档为准），所以别存起来慢慢用，到手就换。

🎫 第四步：code 换 token、拉用户信息 ​

用 code 换票（服务器端做）：

bash
curl "https://api.weixin.qq.com/sns/oauth2/access_token?appid=你的AppID&secret=你的Secret&code=刚拿到的CODE&grant_type=authorization_code"
1

✅ 你应该看到： 返回 {"access_token":"...","expires_in":7200,"openid":"oXXXX...","scope":"snsapi_userinfo"}——openid 到手。

scope 为 userinfo 时，再拉用户资料：

bash
curl "https://api.weixin.qq.com/sns/userinfo?access_token=网页授权token&openid=用户的OPENID&lang=zh_CN"
1

✅ 你应该看到： 返回包含 nickname（昵称）、headimgurl（头像地址）等字段的 JSON。

注意：两把 token 别搞混

本章的「网页授权 access_token」（/sns/ 开头的接口用）与第 2 章「cgi-bin access_token」（/cgi-bin/ 开头的接口用）是两种票据，互不通用。前缀 /sns/ 与 /cgi-bin/ 是分辨它们的口诀。

💻 动手实践：一个能「认人」的网页 ​

下面这个零依赖 Node 服务包含两个入口：/login 负责把用户送去授权，/oauth/callback 负责接 code、换信息、展示昵称。

js
// oauth-demo.js —— 零依赖，Node 18+
const http = require('http')

const APPID = '你的AppID或测试号appid'
const SECRET = '你的Secret或测试号secret'
const BASE = '你的内网穿透域名' // 形如 https://xxxx.cpolar.io，结尾不带斜杠

// 1. 拼授权链接
function buildAuthUrl() {
  const redirect = encodeURIComponent(BASE + '/oauth/callback')
  return (
    'https://open.weixin.qq.com/connect/oauth2/authorize' +
    '?appid=' + APPID +
    '&redirect_uri=' + redirect +
    '&response_type=code' +
    '&scope=snsapi_userinfo' +
    '&state=abc123' +
    '#wechat_redirect'
  )
}

// 2. code 换 token，再拉用户信息
async function getUserByCode(code) {
  const tokenUrl =
    'https://api.weixin.qq.com/sns/oauth2/access_token' +
    '?appid=' + APPID + '&secret=' + SECRET +
    '&code=' + code + '&grant_type=authorization_code'
  const token = await (await fetch(tokenUrl)).json()
  if (!token.openid) throw new Error('换票失败：' + JSON.stringify(token))

  const userUrl =
    'https://api.weixin.qq.com/sns/userinfo' +
    '?access_token=' + token.access_token +
    '&openid=' + token.openid + '&lang=zh_CN'
  const user = await (await fetch(userUrl)).json()
  return user
}

http.createServer(async (req, res) => {
  const u = new URL(req.url, BASE)
  if (u.pathname === '/login') {
    res.writeHead(302, { Location: buildAuthUrl() })
    res.end()
    return
  }
  if (u.pathname === '/oauth/callback') {
    const code = u.searchParams.get('code')
    if (!code) { res.end('缺少 code，请从 /login 重新进入'); return }
    try {
      const user = await getUserByCode(code)
      res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' })
      res.end('<h1>你好，' + user.nickname + '！</h1>' +
        '<p>openid：' + user.openid + '</p>' +
        '<img src="' + user.headimgurl + '" width="64"/>')
    } catch (e) {
      res.end('出错了：' + e.message)
    }
    return
  }
  res.end('访问 /login 开始授权')
}).listen(3000, () => console.log('已启动：http://localhost:3000'))

从零运行步骤：

  1. 修改文件顶部的 APPID、SECRET、BASE（用测试号 + 第 0 章的隧道域名）
  2. 在测试号沙盒页把隧道域名登记为「网页授权域名」
  3. 终端运行 node oauth-demo.js
  4. 用手机微信（不是电脑浏览器）打开 隧道域名/login，点击「同意授权」
  5. ✅ 你应该看到： 页面显示「你好，你的微信昵称！」、一串 o 开头的 openid 和你的头像。授权流程全通。

✏️ 分级练习 ​

  1. 🟢 跟做型：跑通上面的 demo，把「同意授权 → 看到昵称」的过程截图记录。
  2. 🟡 修改型：把 scope 改成 snsapi_base 再走一遍，观察两处变化：不再弹授权页、回调页报「拉取信息失败」（base 拿不到 userinfo 权限）。
  3. 🔴 创作型：在回调页把 openid 和昵称打印到终端并暂存到内存 Map 里，实现「同一个用户第二次进来直接显示上次的信息」。

⚠️ 常见坑 ​

  • 页面提示「redirect_uri 域名与公众号配置不一致」（错误码 10003，以官方文档为准） → 后台没登记域名，或协议 / 子域名填得不完全一致 → 逐字符核对 BASE 与后台登记值
  • errcode: 40163, errmsg: "code been used" → code 是一次性的，你刷新了回调页，浏览器又拿旧 code 换了一次 → 从 /login 重新走完整流程
  • errcode: 40029, errmsg: "invalid code" → code 超过 5 分钟或被截断 → 检查链接拼接、确认编码后立即使用
  • 电脑浏览器打开授权链接报错或空白 → OAuth 必须在微信内置浏览器里进行 → 用手机微信访问链接；电脑调试可用开发者工具的「公众号网页调试」

拿到了 openid 和昵称，网页只是「认识」了用户。想让分享卡片变好看、想拿到用户的 GPS 定位，就要请出 JSSDK——先学一个新词：签名。

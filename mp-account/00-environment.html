🎯 学习目标 ​

读完本章，你将能够：

  • 能注册一个个人订阅号并顺利进入后台
  • 能说清为什么需要内网穿透，并任选 natapp 或 cpolar 跑通一条隧道
  • 能用 curl 发出 GET / POST 请求，看懂状态码、JSON 和请求头
  • 能用 curl 调通一个公开接口，验证本机环境全部就绪

📇 术语卡 ​

术语白话解释
订阅号公众平台四种账号之一，像「自媒体」，主打每天发文章，个人可注册
内网穿透给你家里的电脑开一扇「公网小门」，让外面的人能访问到你本机的服务
curl命令行里发的「网络快递」，一行命令就能向服务器要数据、传数据
HTTP浏览器和服务器之间送「请求」、收「响应」的一套规矩
状态码服务器回的一句话暗号：200 成功、404 找不到、500 我这边炸了
JSON长得像 { "名字": "值" } 的数据格式，程序之间用它传话
请求头快递单上的附加信息，比如「我发的是 JSON」「我的身份是什么」
回调微信服务器主动把消息送到你配置的网址上，这个动作叫回调

📮 注册一个个人订阅号 ​

咱们这门课的「操作对象」。个人订阅号免费、注册门槛低，学接口开发足够用。

第 1 步：打开注册页

浏览器访问 https://mp.weixin.qq.com，点击右上角「立即注册」。

✅ 你应该看到： 页面上摆着四种账号类型卡片：订阅号、服务号、小程序、企业微信。

第 2 步：选择「订阅号」

点击订阅号卡片。（区别在下一章细讲，先选它没跑）

✅ 你应该看到： 进入「信息填写」页，第一步要求填写邮箱。

第 3 步：填邮箱并激活

填一个没注册过公众平台的邮箱，接收 6 位验证码邮件并填入，再设置登录密码。

✅ 你应该看到： 邮箱里收到「微信公众平台验证码」邮件，填入后进入下一步。

第 4 步：选择注册地与主体类型

注册地选「中国大陆」，主体类型选「个人」。

✅ 你应该看到： 主体类型列表包含：政府、媒体、企业、其他组织、个人，你勾中了「个人」。

第 5 步：信息登记

如实填写管理员姓名、身份证号，用本人手机接收验证码，最后用你自己的微信扫码绑定管理员身份。

✅ 你应该看到： 手机上弹出「确认注册」提示，点击确认后页面显示注册成功。

第 6 步：设置账号信息

设置账号名称（想一个不重复的）、功能介绍、选择运营地区，提交。

✅ 你应该看到： 跳转进入公众号后台首页，左侧有一列菜单：「内容与互动」「广告与服务」「设置与开发」等。到这里，你的号就注册好了。

注意

账号名称有唯一性限制，起名规则与修改次数以官方文档为准。想好再填，别用「测试123」这种以后会后悔的名字。

🕳️ 为什么需要内网穿透 ​

先想一个流程：用户给你的公众号发消息，微信服务器要把这条消息送到你写的程序里。可你的程序跑在自己电脑上，而你的电脑躲在路由器后面，没有公网 IP——微信在外面敲门，根本敲不到你家门。

内网穿透就是雇一个「门卫中转站」：

text
微信服务器 → 中转站的公网域名 → 隧道 → 你本机的 3000 端口
1

你把中转站给的域名填到公众号后台，微信的消息就能拐个弯进你的电脑。下面两款工具二选一即可。

方案 A：natapp ​

第 1 步：打开 https://natapp.cn 注册账号，在后台「购买隧道」里买一条免费隧道（web 协议，本地端口填 3000）。

✅ 你应该看到： 隧道列表里出现一条隧道，点开能看到一串 authtoken。

第 2 步：官网下载对应系统的客户端，解压后进入目录，终端运行（Windows 用 natapp.exe）：

bash
./natapp -authtoken=你的authtoken
1

✅ 你应该看到： 终端打印 Tunnel established，还有一行 Forwarding http://xxxx.natappfree.cc -> 127.0.0.1:3000。这行公网域名就是你的门牌号，先抄下来。

方案 B：cpolar ​

第 1 步：打开 https://www.cpolar.com 注册，下载客户端（macOS 也可用 brew install cpolar）。

第 2 步：按官网指引执行 cpolar authtoken 你的token 完成认证，然后运行：

bash
cpolar http 3000
1

✅ 你应该看到： 终端（或自动弹出的网页）显示一条公网 URL，形如 https://xxxxxx.cpolar.io，同样抄下来。

注意

免费隧道的公网域名每次重启都会变。变了以后去公众号后台改一下配置就行，学习阶段完全够用；正式上线才需要固定域名 + 备案服务器。

🌐 HTTP 最小知识 ​

公众号接口全是 HTTP + JSON，先花十分钟把这些「暗号」看懂，后面就不慌。

GET：向服务器「要」东西 ​

bash
curl "https://jsonplaceholder.typicode.com/todos/1"
1

✅ 你应该看到： 终端打印一行 JSON：{"userId":1,"id":1,"title":"delectus aut autem","completed":false}——你刚才完成了一次完整的 GET 请求。

状态码：服务器的「表情」 ​

给 curl 加 -i 参数，能看到响应头：

bash
curl -i "https://jsonplaceholder.typicode.com/todos/1"
1

✅ 你应该看到： 输出第一段是响应头，其中一行是 HTTP/2 200——200 就是「成功」。

状态码白话
200成功
301 / 302数据搬家了，去新地址找
404你要的东西不存在
401 / 403没带门票或票不对（公众号接口最常见的坎）
500服务器自己出错了

请求头与 POST：向服务器「交」东西 ​

POST 请求把数据放在请求体里，并用请求头声明数据类型：

bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"title":"buy milk","completed":false}' \
  "https://jsonplaceholder.typicode.com/todos"
1
2
3
  • -X POST：换用 POST 方法
  • -H：加一个请求头，告诉服务器「我发的是 JSON」
  • -d：请求体，就是真正的数据

✅ 你应该看到： 返回 {"title":"buy milk","completed":false,"id":201}——id: 201 说明服务器收下了，还给你编了个号。

JSON 三分钟看懂 ​

json
{
  "name": "小码",
  "age": 18,
  "tags": ["新手", "爱提问"],
  "pet": { "name": "二哈", "age": 2 }
}

  • 大括号 {} 是对象，装「键值对」；中括号 [] 是数组，装一串值
  • 键必须带双引号，多层数据可以嵌套——公众号接口的返回全是这个套路

✏️ 分级练习 ​

  1. 🟢 跟做型：把 POST 示例里 -d 的内容改成 {"title":"learn curl"}，运行后找到返回里那个新的 id，抄在笔记上。
  2. 🟡 修改型：给 GET 请求加 -H "Accept: application/json"，观察响应头有什么变化；再故意请求一个不存在的地址 /todos/9999，看看状态码变成多少。
  3. 🔴 创作型：把内网穿透跑起来，用文字画出「微信 → 隧道 → 本机」的三步链路，并把公网域名和本机端口写进你的学习笔记（第 5 章会用到）。

⚠️ 常见坑 ​

  • 邮箱收不到验证码 → 邮件被分到垃圾箱，或邮箱服务商延迟 → 翻垃圾箱、点「重新发送」，还不行换一个邮箱重来
  • natapp 报 tunnel not exist 或鉴权失败 → authtoken 复制串了行，或隧道 id 和 token 搞混 → 回官网隧道详情页重新完整复制
  • curl: (6) Could not resolve host → 网络不通或本地代理在捣乱 → 关掉代理/VPN 换网络重试
  • Windows 命令提示符里 -d 那行报错 → cmd 对单引号支持不好 → 改用 Git Bash 运行，或外层用双引号、内层引号加 \ 转义

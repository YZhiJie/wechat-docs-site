🟠 第 6 章 · 模板消息 ​

本章信息

难度：🟠 实战 · 预计学习 40 分钟 · 前置：第 5 章 · 消息与素材接口

🎯 学习目标 ​

读完本章，你将能够：

  • 能说清模板消息与订阅通知的现状和区别
  • 能在后台（或测试号）申请一个模板并拿到 template_id
  • 能用 curl 和 Node.js 发送一条带颜色、带跳转的模板消息
  • 能对照 errcode 快速定位 43004 / 40037 等常见报错

📇 术语卡 ​

术语白话解释
模板消息一种格式统一的「通知卡片」，主动推到用户会话里，老账号能力
订阅通知模板消息的升级替代：用户订阅一次才能收一条，新账号走这套
template_id模板的身份证号，从模板库里选用后获得
touser收件人的 openid，谁收就填谁
data卡片上每个字段的内容，键名必须与模板占位符一一对应
跳转配置点击卡片可以跳网页（url）或跳小程序（miniprogram 字段）
errcode微信返回的错误码，0 是成功，其他按官方「全局返回码说明」查

🧭 现状说明：先看清再动手 ​

公众号「主动通知」能力正处于新旧交替期，动手前先弄明白：

  • 模板消息（旧）：部分早期认证账号仍在使用，一次申请长期使用
  • 订阅通知（新）：模板消息的升级替代品。一次性订阅 = 用户订阅一次、你只能发一条；「长期订阅」仅对政务民生等特定行业开放（以官方文档为准）
  • 权限门槛：两者都主要面向认证服务号，个人订阅号没有该能力

注意：以官方文档为准

入口位置、类目规则、订阅次数限制都在持续调整，本节只讲流程骨架，一切细节以官方文档和后台实际展示为准。学习阶段用「测试号」的模板消息功能练手，代码与正式号完全一致。

📋 第一步：申请一个模板 ​

正式号路径（有权限时）： 后台「广告与服务 → 模板消息」（或新版「订阅通知」入口）→ 从类目库中选用合适模板 → 详情页拿到 template_id。

测试号路径（学习推荐）： 测试号沙盒页找到「模板消息接口」→ 点「新增测试模板」→ 填标题与内容，内容里用占位符：

text
{{first.DATA}}
签到日期：{{keyword1.DATA}}
连续天数：{{keyword2.DATA}}
{{remark.DATA}}

🚀 第二步：发送接口（JSON 三要素） ​

逐字段说明（字段与行为以官方文档为准）：

  • touser：openid，第 3 章 OAuth 或第 5 章消息里都能拿到
  • url：可选。用户点击卡片后跳转的网页；也可以换成 miniprogram 字段跳小程序
  • data：键名必须和模板占位符完全一致（first、keyword1……remark 是常见占位）；value 是内容，color 可选（十六进制色值，不填走微信默认色）

✅ 你应该看到： 发送成功时返回 {"errcode":0,"errmsg":"ok","msgid":2xxxxxxx}。

🚦 第三步：频次与触达规则 ​

主动通知不是想发多少发多少，两道闸门：

  1. 接口调用频次：每个接口有每日 / 每分钟限额，超了返回 45009（数字以官方文档为准）
  2. 用户触达规则：模板消息受用户接收规则约束；订阅通知更严格——用户没订阅就发不出去（报 43101）

注意

订阅通知的「订阅一次发一条」是硬约束：用户 A 订阅了 1 次，你最多能给他发 1 条。想长期提醒，要在每次触达后引导用户再次订阅。规则细节以官方文档为准。

💻 动手实践：发出你的第一条通知 ​

js
// send-template.js —— 复用第 2 章的 token.js，Node 18+
const { getToken } = require('./token')

const OPENID = '用户的openid（测试号页面能查到自己的）'
const TEMPLATE_ID = '你的template_id'

async function sendTemplate(openid, templateId, data, jumpUrl) {
  const token = await getToken()
  const url =
    'https://api.weixin.qq.com/cgi-bin/message/template/send' +
    '?access_token=' + token
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      touser: openid,
      template_id: templateId,
      url: jumpUrl || '',
      data: data
    })
  })
  const result = await res.json()
  if (result.errcode !== 0) {
    throw new Error('发送失败：' + JSON.stringify(result))
  }
  console.log('发送成功，msgid：', result.msgid)
  return result
}

async function main() {
  await sendTemplate(OPENID, TEMPLATE_ID, {
    first: { value: '签到成功', color: '#173177' },
    keyword1: { value: '2026-10-22' },
    keyword2: { value: '连续签到 3 天' },
    remark: { value: '明天继续哦', color: '#10B981' }
  }, 'https://example.com/checkin')
}

从零运行步骤：

  1. 在测试号沙盒页新增测试模板（占位符用 {{first.DATA}} 等），复制 template_id
  2. 用微信扫码关注测试号，沙盒页面右侧能看到你自己的 openid，复制下来
  3. 把 OPENID、TEMPLATE_ID 填进 send-template.js，确认同目录有第 2 章的 token.js
  4. 终端运行 node send-template.js
  5. ✅ 你应该看到： 终端打印「发送成功，msgid：…」；微信「服务通知」里出现一张卡片：签到成功 / 2026-10-22 / 连续签到 3 天，标题和备注分别是深蓝与绿色

✏️ 分级练习 ​

  1. 🟢 跟做型：用测试号发出第一条模板消息，把终端返回与手机卡片截图记录。
  2. 🟡 修改型：模板里加一个 keyword3（如「今日积分」），data 同步增加字段后重新发送，验证占位符与 data 键必须一一对应。
  3. 🔴 创作型：封装 checkinNotify(openid, days) 函数：days 不同返回不同 first 文案与颜色；发送失败时按 errcode 查表打印中文原因（对照下文常见坑表格）。

⚠️ 常见坑 ​

  • errcode: 40037, errmsg: "invalid template_id" → template_id 抄错、多了空格，或模板不属于当前账号 → 回模板列表逐字符核对
  • errcode: 43004, errmsg: "require subscribe" → 收件用户尚未关注公众号 → 先引导用户关注，再发送
  • errcode: 43101, errmsg: "user refused to accept" → 订阅通知场景下用户没订阅或拒收 → 让用户先完成一次订阅动作，再发
  • data 里发了模板占位符没有的字段 → 卡片上静默不显示，或触发参数错误（行为以官方文档为准）→ 占位符与 data 键逐一对照，一个不多一个不少

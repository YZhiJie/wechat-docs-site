🟡 第 4 章 · 自定义组件进阶 ​

本章信息

难度：🟡 进阶 · 预计学习 60 分钟 · 前置：第 3 章 · 组件与基础 API

🎯 学习目标 ​

读完本章，你将能够：

  • 能创建组件四件套并用 usingComponents 注册
  • 能用 properties 接收父组件传进来的值
  • 能用 triggerEvent 把组件里发生的事通知父组件
  • 能用 slot 让父组件往组件里「塞内容」
  • 能理解样式隔离，知道全局样式为什么不进组件

📇 术语卡 ​

术语白话解释
自定义组件自己造的积木：结构、样式、逻辑、配置打包复用
Component 构造器造积木的模具，Component({...}) 里填配置
properties组件的「入参」，父页面传值进来
triggerEvent组件对外的「喇叭」，喊一声事件给父页面听
slot组件预留的「空插槽」，父页面往里塞内容
usingComponents页面或全局配置里的「零件清单」，注册后才能用
样式隔离组件内外样式默认互不干扰的机制

🧩 组件：可复用的积木 ​

第 3 章的 button、view 是官方积木；自定义组件是你自己造的积木。造一个组件 = 建一个文件夹，放齐四件套：

📥 properties：父传子 ​

父页面这样用：<rate value="3" max="5" />。组件里用 properties 接住，用法和 data 一样：

js
Component({
  properties: {
    value: { type: Number, value: 0 },  // 当前评分，默认 0
    max: { type: Number, value: 5 }     // 总共几颗星，默认 5
  }
})

📤 triggerEvent：子告诉父 ​

组件内部发生了值得汇报的事（比如用户点了星星），就「按喇叭」：

js
this.triggerEvent('change', { value: 4 })  // 事件名 + 要捎带的数据
1

父页面用 bind + 事件名接住，数据在 e.detail 里：

wxml
<rate value="{{ score }}" bindchange="onRate" />
1
js
onRate(e) {
  this.setData({ score: e.detail.value })  // 4 就藏在 e.detail 里
}
1
2
3

组件永远不直接改父页面的数据，它只喊一嗓子，改不改由父页面决定。

🙈 样式隔离 ​

默认情况下：组件的样式出不去，外面的样式也进不来。三个推论要记牢：

  1. 组件里写 .star { color: red }，只影响本组件，不会误伤页面
  2. app.wxss 里的全局样式不会作用到自定义组件内部
  3. 组件的 wxss 里只用类选择器，标签选择器（如 text {...}）在组件里不生效

确实需要页面样式进入组件时，可以在组件里开启：

js
Component({
  options: {
    styleIsolation: 'apply-shared'  // 页面样式会影响组件（默认是 isolated）
  }
})

新手建议保持默认隔离，样式问题会少一大半。

💻 动手实践：完整可抄的星星评分组件 ​

组件四件套（新建 components/rate/ 文件夹）：

js
// 星星评分组件：父传 value/max，点星星触发 change 事件
Component({
  properties: {
    value: { type: Number, value: 0 },  // 当前评分
    max: { type: Number, value: 5 }     // 总共几颗星
  },
  data: {
    list: []
  },
  lifetimes: {
    attached() {
      this.buildList()   // 组件挂载时生成星序列表
    }
  },
  observers: {
    max() {
      this.buildList()   // max 变了就重建列表
    }
  },
  methods: {
    buildList() {
      const list = []
      for (let i = 1; i <= this.data.max; i++) {
        list.push(i)
      }
      this.setData({ list })
    },
    onTapStar(e) {
      const value = e.currentTarget.dataset.star
      this.setData({ value })
      // 向父页面广播新评分
      this.triggerEvent('change', { value: value })
    }
  }
})

从零运行步骤：

  1. 打开 examples/native-demo 项目，根目录新建文件夹 components/rate
  2. 在里面新建 rate.js、rate.json、rate.wxml、rate.wxss 四个文件，逐个粘贴上面代码
  3. 新建 pages/demo 的 json、wxml、js 三个文件（wxss 可留空），粘贴页面三段代码
  4. 打开 app.json，在 pages 数组里加一行 "pages/demo/demo"，保存
  5. ✅ 你应该看到： 模拟器切到 demo 页，显示 5 颗星，其中 3 颗是橙色的（value 初始为 3）
  6. 点第 5 颗星
  7. ✅ 你应该看到： 五颗星全部变亮，下方显示「当前评分：5 分」，并弹出「评了 5 分」的 Toast
  8. 点第 1 颗星
  9. ✅ 你应该看到： 只亮 1 颗——点谁亮到谁，父页面的 data 跟着组件事件一起变

✏️ 分级练习 ​

  1. 🟢 跟做型：把 demo 页 data.score 改成 0，观察初始状态；再点满 5 颗星，确认 Toast 数字正确。
  2. 🟡 修改型：给组件新增一个 size 属性（Number 类型）控制星星字号——在组件 wxml 的 text 标签上加内联样式，字号写成「双大括号包住 size 再拼上 rpx」的形式，页面上传 size="80" 试试。
  3. 🔴 创作型：仿照 rate 写一个 counter 步进器组件（− / + 两个按钮），properties 收 value，点按钮时 triggerEvent('change')，放进 demo 页和评分组件并排显示。

⚠️ 常见坑 ​

  • Console 报 Component is not found in path "components/rate/rate" → json 忘写 "component": true，或 usingComponents 路径写错 → 补上声明，路径以 / 开头表示从项目根目录找
  • Console 警告 Never modify data or properties... → 组件里直接改 properties 传进来的值 → 用 setData 改自己的 data，并通过 triggerEvent 让父页面去改源头
  • 组件里写 text { color: red } 毫无效果 → 组件样式只认类选择器 → 全部改用 .类名
  • 父页面 bindchange 收不到事件 → triggerEvent('Change') 事件名带大写或两边拼写不一致 → 事件名保持全小写，父页面写 bind + 同名

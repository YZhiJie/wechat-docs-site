🟢 第 2 章 · WXML、WXSS 与生命周期 ​

本章信息

难度：🟢 入门 · 预计学习 50 分钟 · 前置：第 1 章 · 注册与工具链

🎯 学习目标 ​

读完本章，你将能够：

  • 能用双大括号把 JS 数据绑定到页面上
  • 能用 wx:if 控制显示、用 wx:for 渲染列表
  • 能理解 rpx 单位并写出自适应样式
  • 能说出 App 与 Page 生命周期钩子的执行顺序
  • 能分清 onLoad 和 onShow 各该干什么

📇 术语卡 ​

术语白话解释
WXML小程序的页面结构文件，类似 HTML，负责「摆什么」
WXSS小程序的样式文件，类似 CSS，负责「长什么样」
插值双大括号语法，把 JS 里的数据「嵌」进页面显示
条件渲染wx:if：条件成立才渲染这块内容
列表渲染wx:for：数组有几项就生成几块内容
rpx响应式像素，750rpx 永远等于一屏宽
生命周期程序或页面「从生到死」各阶段自动触发的函数
setData页面更新数据的唯一正道，改完页面自动刷新

🧱 WXML：页面的骨架 ​

数据绑定：双大括号 ​

JS 的 data 里放数据，WXML 用双大括号取出来显示。数据一变，页面自动跟着变：

wxml
<!-- examples/native-demo/pages/index/index.wxml（节选） -->
<view class="title">你好，{{ userName }}！</view>
<button type="primary" bindtap="addCount">点我 +1（已点 {{ count }} 次）</button>

3

双大括号里还能做简单运算，页面上会直接显示算出来的结果：

wxml
<view>1 + 1 = {{ 1 + 1 }}</view>
<view>两倍是：{{ count * 2 }}</view>

2

条件渲染：wx:if ​

条件成立才渲染这块内容，和 JS 的 if 是一个意思：

wxml
<view wx:if="{{ score >= 60 }}">及格啦</view>
<view wx:else>再接再厉</view>
1
2

列表渲染：wx:for ​

数组有几项，就自动生成几块内容。item 是当前项、index 是下标；顺手写上 wx:key，帮助框架识别每一项：

wxml
<view wx:for="{{ todos }}" wx:key="*this">{{ index }} - {{ item }}</view>
1

🎨 WXSS：给页面穿衣服 ​

rpx：会伸缩的像素 ​

rpx 是小程序发明的单位，规则一句话：750rpx 永远等于一屏宽。所以设计稿按 750 宽出图，量到多少就写多少，到哪台手机都自动缩放：

屏幕实际屏宽1rpx 等于
小屏机320px约 0.42px
iPhone 6/7/8375px0.5px
大屏机414px约 0.55px

常用选择器 ​

最常用就两个：page 管整个页面默认样式，.类名 管对应标签。下面是示例项目的全局样式：

wxss
/* 全局样式 */
page {
  background-color: #f8fafc;  /* page 选择器：整个页面 */
  font-size: 28rpx;
  color: #334155;
}

.container {
  padding: 40rpx;             /* 类选择器：对应 class="container" */
}

.mt {
  margin-top: 24rpx;
}

🔄 生命周期：小程序的一生 ​

「生命周期」就是程序在关键节点自动调用的函数，你把代码放进对应钩子，时机到了它自己执行。

应用级：App 的三个钩子 ​

钩子时机典型用途
onLaunch小程序第一次启动，只来一次初始化、读缓存
onShow启动或从后台切回前台刷新状态
onHide按 Home 键、切到别的 App暂停、暂存数据
js
// 应用启动入口
App({
  onLaunch() {
    // 记录启动时间，供 logs 页面展示
    const logs = wx.getStorageSync('launch_logs') || []
    logs.unshift(Date.now())
    wx.setStorageSync('launch_logs', logs.slice(0, 10))
    console.log('App onLaunch')
  },
  onShow() {
    console.log('App onShow')
  },
  onHide() {
    console.log('App onHide')
  },
  globalData: {
    userName: '小码'
  }
})

页面级：Page 的四个钩子 ​

钩子时机典型用途
onLoad页面加载，只执行一次，能拿到跳转参数读参数、初始化数据
onShow页面每次露面（含从别的页返回）刷新倒计时、拉新消息
onReady页面初次渲染完成需要节点尺寸的操作
onUnload页面被关闭清理定时器
js
const { formatTime } = require('../../utils/util')
const app = getApp()

Page({
  data: {
    userName: '',
    count: 0,
    now: ''
  },
  onLoad() {
    this.setData({
      userName: app.globalData.userName,
      now: formatTime(new Date())
    })
  },
  onShow() {
    console.log('Index onShow')
  },
  addCount() {
    // setData 是唯一正确的数据更新方式
    this.setData({ count: this.data.count + 1 })
  },
  goLogs() {
    wx.navigateTo({ url: '/pages/logs/logs' })
  }
})

onLoad 与 onShow 的区别 ​

对比点onLoadonShow
执行次数只一次每次露面都执行
从别的页返回时不执行执行
适合放接参数、一次性初始化每次都要刷新的逻辑

启动日志页就是在 onLoad 里读缓存，再交给 wx:for 渲染：

wxml
<view class="container">
  <view class="tip">最近 10 次启动时间：</view>
  <view class="log-item" wx:for="{{ logs }}" wx:key="*this">{{ item }}</view>
</view>

注意

改数据必须用 this.setData。直接写 this.data.count = 5 只改了内存里的值，页面纹丝不动——这是新手第一大坑。

💻 动手实践：观察生命周期的真实顺序 ​

从零运行步骤：

  1. 打开微信开发者工具，按第 1 章方式 B 导入 examples/native-demo，AppID 选「测试号」
  2. 点工具栏「编译」，盯着右侧调试器的 Console 面板
  3. ✅ 你应该看到： 依次输出 App onLaunch → App onShow → Index onShow，这就是启动顺序
  4. 点三次「点我 +1」按钮
  5. ✅ 你应该看到： 按钮上的数字变成 3——双大括号绑定的值被 setData 更新了
  6. 点「查看启动日志」进入日志页
  7. ✅ 你应该看到： 一列启动时间，每条一个白底圆角卡片（wx:for 渲染的）
  8. 点模拟器右上角「···」选「切后台」，再切回前台
  9. ✅ 你应该看到： Console 新增 App onHide 和 App onShow，但没有 App onLaunch——它一辈子只跑一次

✏️ 分级练习 ​

  1. 🟢 跟做型：在首页 wxml 加一行 view，用双大括号直接显示 count 的两倍（在大括号里写算式即可）。
  2. 🟡 修改型：给日志页每一条前面加上序号，利用 wx:for 自带的 index。
  3. 🔴 创作型：新建一个 profile 页面，在 onLoad 里 setData 自己的名字和一句口号，页面上用双大括号展示（提示：记得在 app.json 的 pages 里注册新页面）。

⚠️ 常见坑 ​

  • 点按钮数字不变 → 写成了 this.data.count = 5 直接赋值 → 改用 this.setData({ count: 5 })
  • Console 黄色警告 Now you can provide attr "wx:key" for a "wx:for" → 列表没写 wx:key → 补上 wx:key="*this" 或唯一字段名
  • 每次返回页面逻辑重复执行（如重复弹窗、重复计数） → 初始化代码放错了钩子 → 只跑一次的放 onLoad，onShow 只放「每次都要刷新」的
  • 改了 WXML 模拟器没反应 → 文件没保存，或关闭了自动编译 → Ctrl / Cmd + S 保存，必要时手动点「编译」

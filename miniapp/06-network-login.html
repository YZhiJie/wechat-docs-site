🟡 第 6 章 · 网络请求与登录态 ​

本章信息

难度：🟡 · 预计学习 45 分钟 · 前置：第 5 章 · 分包加载

🎯 学习目标 ​

  • 说出 wx.request 的核心参数和三个回调的触发时机
  • 独立完成服务器域名白名单配置
  • 用 Promise 封装一个可复用的请求模块
  • 按「文字时序图」讲清 wx.login 的完整登录流程
  • 把 token 存到本地，并在每次请求头里自动携带

📇 术语卡 ​

术语白话解释
wx.request小程序里发 HTTP 请求的 API，相当于浏览器里的 fetch/ajax
HTTPS加密版的 HTTP，小程序强制要求接口必须是 HTTPS
域名白名单官方后台配置的「允许请求的域名清单」，不在名单里就拦截
回调函数把一个函数交给 API，等它干完活再回头调用它，如 success/fail
Promise把回调改成 .then() 链式写法的对象，解决「回调地狱」
token服务端发的「通行证」，之后每次请求带上它证明你是谁
code2session微信官方接口：服务端用 code 换 openid 的动作
登录态「当前用户已登录」这个状态，通常由 token 是否有效来代表

🌐 wx.request：小程序里发请求 ​

小程序没有浏览器的 fetch 和 XMLHttpRequest，发请求要用官方提供的 wx.request。它最常用的参数有五个：

参数作用常见取值
url请求地址必须是 HTTPS 且在白名单里
method请求方法默认 GET，常用 POST
data请求参数对象，GET 会拼到网址上，POST 放请求体
header请求头如 content-type、Authorization
success / fail / complete回调成功 / 失败 / 无论成败都会执行

来实际发一个请求。在 pages 下新建页面 request，把逻辑写成这样：

js
// pages/request/request.js
Page({
  data: { loading: false, result: '', error: '' },
  fetchTodo() {
    this.setData({ loading: true, error: '' })
    wx.request({
      url: 'https://jsonplaceholder.typicode.com/todos/1',
      method: 'GET',
      data: {},
      header: { 'content-type': 'application/json' },
      success: (res) => {
        // 注意：HTTP 404/500 也会走 success，必须自己判断 statusCode
        if (res.statusCode === 200) {
          this.setData({ result: JSON.stringify(res.data, null, 2) })
        } else {
          this.setData({ error: 'HTTP ' + res.statusCode })
        }
      },
      fail: (err) => {
        this.setData({ error: err.errMsg || '请求失败' })
      },
      complete: () => {
        this.setData({ loading: false })
      }
    })
  }
})

注意：success 不等于业务成功

success 只代表「HTTP 通信完成了」。接口返回 404、500 时依然走 success，所以业务代码里必须自己判断 res.statusCode，只把 2xx 当成功处理。

📋 域名白名单：为什么真机上请求失败 ​

小程序出于安全考虑，只允许请求你在官方后台登记过的域名。开发工具里可以临时关掉校验，但真机体验版和正式版一定会被拦截。配置步骤：

  1. 登录 微信公众平台，进入你的小程序后台
  2. 左侧「开发」→「开发管理」→「开发设置」
  3. 找到「服务器域名」，点击「修改」（需要管理员扫码）
  4. 在「request 合法域名」一栏填入你的接口域名，如 https://api.example.com，保存

✅ 你应该看到： 保存后「request 合法域名」列表里出现你刚填的域名；回到开发者工具重新编译，不再弹出域名校验警告。

注意

  • 域名必须是 HTTPS，且不能用 IP 和端口写法
  • 每月可修改的次数有限制（具体次数以官方文档为准），别当草稿纸用
  • 开发工具的「不校验合法域名」只对开发阶段有效，真机必须走白名单

🎁 封装请求模块：告别回调地狱 ​

真实项目里接口有几十个，每个都写一遍 wx.request 会重复到崩溃。标准做法是用 Promise 包一层，统一处理域名前缀、token 和错误：

js
// utils/request.js —— Promise 版请求封装
const BASE_URL = 'https://api.example.com'

function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: {
        'content-type': 'application/json',
        // 每次请求自动带上 token，下一节会把它存进来
        Authorization: 'Bearer ' + (wx.getStorageSync('token') || '')
      },
      success: (res) => {
        if (res.statusCode >= 200 && res.statusCode < 300) {
          resolve(res.data)
        } else {
          reject(res)
        }
      },
      fail: reject
    })
  })
}

module.exports = { request }

🔐 登录流程：wx.login 换 token 的完整时序 ​

小程序的登录不是输密码，而是一套「凭证交换」流程。整个时序用文字还原如下：

  1. 小程序调用 wx.login()，拿到临时凭证 code（5 分钟内有效、只能用一次，以官方文档为准）
  2. 小程序通过 wx.request 把 code 发给你自己的服务端
  3. 服务端拿着 appid + appsecret + code，去请求微信官方的 code2session 接口
  4. 微信返回该用户的 openid、session_key 等信息
  5. 服务端生成自己的 token（比如 JWT），和 openid 绑定存进数据库
  6. 服务端把 token 返回给小程序
  7. 小程序调用 wx.setStorageSync('token', token) 把它持久化到本地
  8. 之后每次请求都在 header 里带上 Authorization: Bearer token；一旦 token 失效，重新走一遍第 1 步
js
// pages/login/login.js —— 登录态获取与保存
Page({
  doLogin() {
    wx.login({
      success: (res) => {
        // 第 1 步：拿到 code
        wx.request({
          url: 'https://api.example.com/login',
          method: 'POST',
          data: { code: res.code },
          // 第 6 步：服务端返回 token
          success: (r) => {
            // 第 7 步：存到本地
            wx.setStorageSync('token', r.data.token)
          }
        })
      }
    })
  }
})

注意：appsecret 绝对不能放进小程序代码

appsecret 相当于你小程序的钥匙，只能保存在服务端。写在小程序代码里等于把家门钥匙贴在大门上——代码会被打包下载。没有自建服务端时，可以先用云函数顶替（第 8 章会讲）。

✅ 你应该看到： 调用一次 doLogin 后，在调试器 Storage 面板里能看到 token 键和一长串字符串值；之后再发请求，Network 面板里请求头多了 Authorization 字段。

// uni.request 网络请求演示 —— 对应教程《第 6 章 · 网络请求与登录态》
import { ref } from 'vue'

const loading = ref(false)
const result = ref('')
const error = ref('')

function fetchTodo() {
  loading.value = true
  error.value = ''
  uni.request({
    url: 'https://jsonplaceholder.typicode.com/todos/1',

    fail: (err) => {
      error.value = err.errMsg || '请求失败'

      loading.value = false
    }

从零运行步骤：

  1. 确认电脑已装 Node.js 与 pnpm，在仓库根目录执行 pnpm install
  2. 进入示例目录：cd examples/uniapp-demo，执行 pnpm dev:mp-weixin 并保持窗口运行
  3. 打开微信开发者工具 →「导入项目」→ 目录选择 examples/uniapp-demo/dist/dev/mp-weixin → AppID 选「测试号」
  4. 编译完成后模拟器显示首页，点击「查看请求示例」进入请求页
  5. 点击「发起 GET 请求」→ 按钮变为「请求中…」，随后页面显示一段 JSON
  6. 断开网络再点一次 → 出现红色「请求失败：…」，这就是 fail 回调在工作

✏️ 分级练习 ​

  1. 🟢 跟做型：跑通上面的 uni-app 请求示例；然后在 success 里加一行 console.log(res.statusCode)，确认打印的是 200
  2. 🟡 修改型：给 utils/request.js 增加「超时提示」：请求超过 10 秒未返回时 reject 一个「请求超时」错误（提示：查一下 wx.request 的 timeout 参数，具体行为以官方文档为准）
  3. 🔴 创作型：做一个「待办清单」页面：请求 https://jsonplaceholder.typicode.com/todos（返回 200 条数组），用 wx:for 渲染列表，completed 为真的项打勾显示

⚠️ 常见坑 ​

  • 报错 request:fail url not in domain list → 域名没配进白名单 → 去官方后台「开发设置 → 服务器域名」添加；开发阶段可临时勾选「不校验合法域名」，但真机必须配
  • 接口返回 404，代码却执行了 success 里的逻辑 → 误以为 success 等于成功 → 在 success 里判断 res.statusCode，非 2xx 走失败分支
  • 报错 errCode: 40029 invalid code → code 被用了第二次，或超过 5 分钟才发给服务端 → 每次登录都重新调 wx.login 拿新 code
  • 开发工具里好好的，真机一跑就失败 → 真机不认开发工具的「不校验域名」开关 → 老老实实配置 HTTPS 白名单，再检查手机网络

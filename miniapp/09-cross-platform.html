🎯 学习目标 ​

  • 说出「跨端」要解决的问题是什么

📇 术语卡 ​

术语白话解释
跨端一份代码，编译发布到微信/支付宝/百度小程序、H5、App 等多个平台
uni-appDCloud 出品的跨端框架，用 Vue 语法写，编译成各端小程序
Taro京东出品的跨端框架，主打 React 语法（也支持 Vue）
SFCSingle File Component，Vue 的单文件组件，一个 .vue 文件含模板/逻辑/样式
组合式 APIVue 3 的写法风格：用 ref、函数组织代码，对应原生小程序的 data/方法
条件编译用特殊注释让某段代码只在指定平台生效，如 #ifdef MP-WEIXIN
产物编译工具最终输出的代码，如 uni-app 编译出的 mp-weixin 目录

🤔 为什么需要跨端 ​

小程序不止微信一家：支付宝、抖音、百度都有自己的小程序平台，语法各不相同。如果产品要上 4 个平台，原生开发就得写 4 遍——界面一样、逻辑一样，纯粹是换语法重抄。

跨端框架的思路：你用一套通用语法（Vue 或 React）写代码，工具负责编译成各平台的专属代码。一份源码，多端产物。

⚖️ 三大方案对比 ​

维度原生小程序uni-appTaro
语法WXML/WXSS/JS（私有）Vue 3（SFC）React 为主（也支持 Vue）
学习成本要学一套私有模板语法会 Vue 几乎零成本会 React 几乎零成本
生态微信官方，能力最全最稳插件市场丰富，中文资料多社区活跃，大厂用得多
支持平台仅微信微信/支付宝/抖音/H5/App 等微信/支付宝/抖音/H5/RN 等
调试体验开发者工具直连，最直接编译后用开发者工具，多一步同左
适用场景纯微信、追求极致性能与首屏多端需求 + Vue 技术栈多端需求 + React 技术栈

一句话总结：只发微信、追求性能 → 原生；要多端且会 Vue → uni-app；要多端且会 React → Taro。

🔁 uni-app 写法与原生写法的对应关系 ​

这是本章最值钱的一张表——你前 8 章学的原生知识，全部能映射过去。下面引自示例工程 examples/uniapp-demo/README.md 的对应关系表：

原生写法uni-app 写法
Page({ data: { count: 0 } })const count = ref(0)
this.setData({ count: 1 })count.value = 1

wx.navigateTouni.navigateTo
WXML bindtap模板 @click

补充两条本章用到的：

看真实代码感受一下。这是示例工程的首页，逻辑和第 2 章的 native-demo 首页一模一样，只是换了写法：

vue
<!-- 引自示例工程，路径：examples/uniapp-demo/src/pages/index/index.vue -->
<script setup>
// 组合式 API 写法 —— 对应教程《第 9 章》
import { ref } from 'vue'

const count = ref(0)
const userName = ref('小码')

function addCount() {
  count.value += 1
}

function goDemo() {
  uni.navigateTo({ url: '/pages/demo/demo' })
}
</script>

<template>
  <view class="container">
    <view class="title">你好，{{ userName }}！</view>
    <view class="desc">这是 uni-app（Vue 3）版本，代码结构与原生小程序一一对应</view>
    <button type="primary" @click="addCount">点我 +1（已点 {{ count }} 次）</button>
    <button class="mt" @click="goDemo">查看请求示例</button>
  </view>
</template>

对照着读：count = ref(0) 就是 data: { count: 0 }；count.value += 1 就是 setData({ count: +1 })，而且不用 setData 了——Vue 的响应式系统自动帮你更新视图，这正是很多人喜欢 uni-app 的原因。

从零运行步骤：

  1. 确认 Node.js（建议 18+）和 pnpm 已安装，在仓库根目录执行 pnpm install
  2. 进入 examples/uniapp-demo 目录，执行 pnpm dev:mp-weixin，保持终端窗口运行（它在监听文件变化）
  3. 打开微信开发者工具 →「导入项目」
  4. 目录选择 examples/uniapp-demo/dist/dev/mp-weixin（注意：不是项目根目录），AppID 选「测试号」（manifest.json 已预置 touristappid）
  5. 等待编译完成

✅ 你应该看到： 模拟器出现 uni-app 版首页：「你好，小码！」标题、一个「点我 +1」计数按钮和一个「查看请求示例」按钮；点计数按钮数字递增；跳转到请求页后点「发起 GET 请求」能看到 JSON 结果（这就是第 6 章的网络示例）。

  1. 试着改一下 src/pages/index/index.vue 里的标题文案并保存

✅ 你应该看到： 终端里 dev 进程瞬间输出重新编译的日志，开发者工具自动刷新，模拟器里标题变成了新文案。

注意

uni-app 的开发流程是「先编译再调试」：开发者工具打开的是编译产物目录，不是源码目录。改源码必须等 dev 进程编译完，工具里才看得到变化。而原生小程序改完即刻生效——这是两种开发手感的最大差别。

🧭 选型建议 ​

把决策场景摆出来，对号入座：

  1. 只做微信小程序，页面不多、性能敏感（如长列表、复杂动画）→ 原生。没有中间编译层，能力第一时间跟进官方更新，调试直连
  2. 要多端（微信 + 支付宝 + H5 是常见组合），团队熟 Vue → uni-app。你前 8 章的知识几乎无缝迁移，条件编译处理平台差异
  3. 要多端，团队熟 React → Taro。同样的跨端思路，换 React 语法
  4. 拿不准：先用原生把第 10 章的上线流程走通；等真有多端需求，再用 uni-app 重写——有了本课程的对应关系表，重写成本比想象中低得多

注意

跨端框架省的是「重复劳动」，不是「学习成本」。先懂原生再学跨端，遇到编译产物问题、平台差异 bug 时才知道去哪查；反过来先学跨端，很容易被框架和平台两层问题夹在中间无从下手。这也是本课程把跨端放在第 9 章的原因。

✏️ 分级练习 ​

  1. 🟢 跟做型：从零跑通 uniapp-demo，把首页计数加到 10，截图和原生版首页放一起对比两者 UI
  2. 🟡 修改型：给 demo.vue 增加一个 POST 按钮，用 uni.request 向 https://jsonplaceholder.typicode.com/posts 提交一条数据并展示返回的 id
  3. 🔴 创作型：用 uni-app 重写 native-demo 的日志页：wx:for 换成 v-for，wx.getStorageSync 换成 uni.getStorageSync，在模拟器里确认启动日志正常展示

⚠️ 常见坑 ​

  • 报错 uni: command not found 或安装依赖卡住 → 没装 pnpm，或 Node 版本太低 → npm install -g pnpm，Node 升级到 18+（版本要求以官方文档为准）
  • 导入项目后报错找不到 app.json / 页面空白 → 把 uni-app 的源码根目录当成了小程序项目导入 → 应导入编译产物 dist/dev/mp-weixin 目录
  • 改了源码模拟器没反应 → dev 进程已停止，或编译还没完成 → 回终端确认 pnpm dev:mp-weixin 在运行且无报错，再在工具里手动点一次「编译」
  • 代码里写了 wx.request 想发到支付宝端 → wx. 前缀是微信专属，其他端不认 → uni-app 里统一用 uni. 前缀，平台差异用条件编译处理

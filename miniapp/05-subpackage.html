📦 主包与分包：搬家式理解 ​

默认情况下，所有页面都打进主包，用户打开小程序时一次性下载。项目大了会带来两个问题：启动变慢、上传超限。

分包就是把不常用的页面搬进仓库：

  • 主包 = 随身背包：启动立刻下载，只装首页、tabBar 页和高频页面
  • 分包 = 仓库货架：跳到里面的页面时才临时下载，用完的包留在本地
  • 分包可以引用主包的资源（公共工具、样式），主包不能反过来引用分包的资源

配置分包的两个收获：启动只下主包所以更快；包体上限被拆成多个小额度。

⚙️ subPackages：把页面搬进分包 ​

在 app.json 里配置。root 是分包根目录，pages 里写相对 root 的路径，页面的完整路径 = root + 页面路径：

json
{
  "pages": ["pages/index/index"],
  "subPackages": [
    {
      "root": "packageLogs",
      "name": "logs",
      "pages": ["pages/logs/logs"]
    },
    {
      "root": "packageProfile",
      "pages": ["pages/profile/profile"]
    }
  ],
  "window": {
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTitleText": "小码的小程序",
    "navigationBarTextStyle": "black",
    "backgroundColor": "#f8fafc"
  },
  "style": "v2",
  "lazyCodeLoading": "requiredComponents",
  "sitemapLocation": "sitemap.json"
}

三个要点：

  2. name 是给分包起的代号，preloadRule 里引用它更方便（不写也能用 root 代替）
  3. 跳转要写完整路径：wx.navigateTo({ url: '/packageLogs/pages/logs/logs' })

⏩ preloadRule：提前下好 ​

「用到才下载」有一个缺点：第一次跳转要等。preloadRule 解决它——进了某页面，就趁用户闲着把指定分包悄悄下好：

json
"preloadRule": {
  "pages/index/index": {
    "network": "all",
    "packages": ["logs"]
  }
}

  • 键是页面路径：进入这个页面时触发预下载
  • network：all = 任何网络都预下载；wifi = 只在 WiFi 下预下载（包大就选它，别偷用户流量）
  • packages：要预下载的分包，填 name 或 root

注意

同一页面触发预下载的分包总大小有限额（约 2M，以官方文档为准）。给「用户下一步大概率去的地方」配预下载，别见页面就配。

📏 体积红线 ​

上传前务必心里有数（数值会调整，以官方文档为准，文档地址：https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html）：

项目限制说明
单个主包约 2MtabBar 页面必须在主包
单个普通分包约 2M超了就再拆一层
所有分包 + 主包合计约 30M大项目也要省着用

压包的常规三板斧：压缩图片（或改放 CDN）、删掉没用的依赖、把低频页面继续往分包搬。

🏠 独立分包：不依赖主包的特种包 ​

给分包加 "independent": true，它就成了独立分包——用户可以不经过主包直接进入它：

json
"subPackages": [
  {
    "root": "packageAd",
    "independent": true,
    "pages": ["pages/landing/landing"]
  }
]

适用场景： 广告投放落地页、营销活动页——用户从分享卡片直接点进来，不用先加载整个主包，打开速度起飞。

代价与限制：

  • 独立分包里不能依赖主包的内容（组件、工具、样式都算）
  • getApp() 可能拿不到 App 实例（主包没启动），需要时用 getApp({ allowDefault: true })
  • 和所有分包一样，tabBar 页面不能放进来

💻 动手实践：把日志页搬进分包 ​

以 examples/native-demo 为底，把日志页从主包搬进 packageLogs。

从零运行步骤：

  1. 打开 native-demo 项目，在根目录新建文件夹 packageLogs/pages
  2. 把整个 pages/logs 文件夹剪切到 packageLogs/pages 下（logs.js 里的 require('../../utils/util') 层级不变，不用改）
  3. 修改 app.json：从 pages 数组删掉 "pages/logs/logs"，按上面示例加上 subPackages
  4. 修改 pages/index/index.js 里的 goLogs 方法，改成分包完整路径：
js
goLogs() {
  wx.navigateTo({ url: '/packageLogs/pages/logs/logs' })
}

✏️ 分级练习 ​

  1. 🟢 跟做型：完成上面的搬家实操，并在「详情」面板读出主包和分包各自的大小。
  2. 🟡 修改型：新建一个 packageProfile 分包放 profile 页，并配 preloadRule：进首页时在 wifi 下预下载它。
  3. 🔴 创作型：给 packageLogs 加 "independent": true，在 logs.js 里加一行 console.log(getApp())，编译后直接编译到日志页路径，观察它打印了什么（体会独立分包里 getApp() 的坑）。

⚠️ 常见坑 ​

  • 报 Error: pages 'packageLogs/pages/logs/logs' is not found → subPackages 的 root 或 pages 拼错，或跳转 url 没带上分包 root → 完整路径 = root + 页面路径，逐段核对
  • 报 Duplicate page "pages/logs/logs" → 页面搬进分包却没从主包 pages 数组里删除 → 一个页面只允许登记在一个包里
  • 上传报「主包体积超过限制」 → 图片、大依赖堆在主包 → 图片压缩或上 CDN；资源放分包要跟着页面走（主包不能引用分包资源）
  • 把 tabBar 页面写进分包，编译直接报错 → 底部导航的页面必须在主包 → 分包只放普通页面
